# A4 Trust, Safety & Tech audit (2026-11-17)

Good: zod-validated messages, PKCE+state OAuth, HttpOnly cookies, no innerHTML in client, EN/TR profanity, DM link blocks, swear mute, per-type limits.

[A4-1][P1][security] Focus-block credit is forgeable: client sends timer {remainingMs:0,totalMs:3h}, then `finished` records 180 min with no cap per hour; inflates streaks/badges/profile and grows focus_blocks without bound — area-room.ts:645, :897, social-hub.ts:1402 — require timer to have run (server-side start time, remaining<=total-elapsed) and cap blocks per hour per user.
[A4-2][P1][security] Room password guessing has no try limit (only the door code has); unsalted fast SHA-256 of code:password — index.ts:393, social-hub.ts:150 — call passwordTry per account/IP/room and use PBKDF2.
[A4-3][P1][safety] No report function anywhere; only block — protocol.ts, social.ts — add a report message storing sender, text snapshot, area, time for admins.
[A4-4][P1][safety] No account/data deletion (KVKK/GDPR): only character delete, which leaves DMs, shouts, blocks, focus_blocks, sessions and the Google email/sub — social-hub.ts:539 — add "delete my account" purging all tables by account and character ids, plus a data export.
[A4-5][P1][safety] Area `say`, emotes, dances and smoke broadcast to everyone, so a blocked user still reaches the blocker in the same room; only poke/whisper/invite check blocks — area-room.ts:198, :526 — filter broadcasts per recipient via a cached block set, or give a client-side hide.
[A4-6][P1][performance] One SocialHub DO serves all accounts, presence, DMs, shouts and admin; every poke/whisper/invite does an RPC `isBlocked` to it, and each shout loops all sockets with deserializeAttachment — social-hub.ts:1359, area-room.ts:201 — cache blocks in AreaRoom and shard hub by account/shout channel before real traffic.
[A4-7][P2][safety] Blocking sends the blocked person a `blockedBy{name}` event, which invites retaliation — social-hub.ts:1331 — drop the notification (silent block).
[A4-8][P2][stability] DATA_EPOCH bump DROPs users, messages, friends, blocks, focus and rooms tables on next boot; one bad constant edit means total data loss — social-hub.ts:380 — gate behind an explicit env flag and export first.
[A4-9][P2][security] Game tokens carry iat but verifySession does not enforce expiry; a leaked `?token=` in WS URLs (logged) stays valid until the next deploy — auth.ts:86 — enforce a max age (for example 12 h) and prefer a header or first message.
[A4-10][P2][security] WebSocket upgrades check no Origin header, so any site can open sockets using a stolen token; cookie-based /api/me and /api/play POSTs rely only on SameSite=Lax — index.ts:465 — reject mismatched Origin on upgrades and POSTs.
[A4-11][P2][stability] passwordTries Map lives in hub memory, resets on eviction (brute-force window reset) and never prunes old keys — social-hub.ts:171, :629 — store in SQL or prune entries.
[A4-12][P2][safety] Admin is a single env email list plus peer-promoted admins; no audit log of role changes, event approvals, room closes or kicks — social-hub.ts:1260 — log actor, target, time.
[A4-13][P2][stability] AreaRoom state (lastSayAt, tables, jukebox) partly in storage but in-flight timers and `swears` windows rely on attachment size (4 KB limit) as fields grow; `players()` deserializes every socket on each hello — area-room.ts:46, :910 — cap attachment fields and cache the roster.
[A4-14][P3][safety] Shouts are building-wide with history of SHOUT_HISTORY rows shown to new joiners, no admin delete tool for a shout or DM — social-hub.ts:1363 — add admin remove-shout and ban account actions.
